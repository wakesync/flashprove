## Hypothesis
The M1 relation (staged floor, F = 12, one head, D = 128, T = 4) can be proved on the committed product oracle with the RNG approximate range check (blocks/iop/rng.h, with its LKP digit lookup) replacing the 19-bit decomposition of every quotient cell, in ONE proximity-test group: product oracle a,b,c (toy PSC), then RNG's digits and multiplicities messages, then RNG's batched row, then the IOPP. The RNG cells are the product table's own row-0 entries (lanes = 1, the packed matrix is laid directly on the product oracle), so the tie from range cells to product columns is by construction, not by extra wiring relations. delta is split into two limbs delta = 2^18 delta_hi + delta_lo. Under this construction (H1) honest proofs are accepted, (H2) every pre-registered hostile class is rejected, (H3) the range contract holds on the M1 realistic suite at F = 12 including R3, and an honest proof exists on R3 windows where M1 overflowed.

## Metric
Relation, per token, unchanged from M1: P = S^T k (exact), M = floor(a P / 2^2F), delta = floor((v - M) beta / 2^F), S' = floor((a S + k delta^T) / 2^F), o = floor(S'^T q / 2^F). Changes vs M1:
- Quotient cells S', M, delta_lo, delta_hi: range-checked by RNG only (no range bits). Honest contract: |S'|, |M| < 2^18, delta_lo in [0, 2^18), |delta_hi| < 2^18; builder refuses otherwise. All of them form ONE RNG matrix of k = 16 columns (cell (i, c) at product column base + c m + i), window 2D = 2^23 (D = 2^22, digit bits b0 = 12, b1 = 11), so an honest combination is at most 16 x 2^18 = 2^22 in magnitude. What RNG proves per cell: |x| < 2D = 2^23 (approximate check, slack 32x vs the honest contract). No-wrap with 2^23 cells: |a P| <= 2^12 * 128 * 2^23 * 2^12 = 2^54, |delta| <= 2^41 + 2^23, |k delta| <= 2^53: all below p (Goldilocks), so every relation holds over the integers.
- Floor remainders: KEPT as exact unsigned bit decompositions (F or 2F bits, x^2 = x), as in M1. Reason, registered before code: the approximate check proves only |r| < 2D, which admits two (quotient, remainder) pairs for some floors (a 1-ulp rounding choice); floor uniqueness needs an exact interval. Making remainders lookup-exact (direct LKP keys on product cells) is out of scope here and is a listed follow-up.
- v is public: it enters only as relation targets; admissibility widened from |v| < 2^18 to |v| < 2^31 (no-wrap still holds). No private v limbs.
- RNG combinations N = rng_combinations(plan) at the #19 research settings (target 10 bits, 6 work bits on QUERY), toy coins.
Per run: accept, proof bytes, product columns used and table log-length, relations, RNG cell rows / columns / combinations, digit and multiplicity message entries, prove s, verify s, peak RSS. Derived: product columns per state cell per token, and digit + multiplicity entries per state cell per token (reported separately, never summed into a single number without saying so). Compared to M1 #47 (prove 51.43 s, verify 11.63 s, 50,365,792 B, 2,338,816 product gates, ~36 columns per cell per token).
