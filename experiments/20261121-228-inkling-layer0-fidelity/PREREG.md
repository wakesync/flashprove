## The block and its input
**Block.** Layer 0's MoE, from m (the output of `post_attention_layernorm` = checkpoint `mlp_norm`) to the MoE output before `post_mlp_convolution` (`modeling_inkling2_loop.py:908`). `post_mlp_convolution` and the residual are not part of the block.

**Input (float64 only, identical for both arms, open loop).** Token ids -> embedding rows (BF16, exact in float64) -> `embed_norm` RMS norm with gain, eps 1e-6 (`:1240-1246`, `:740-745`) = x. Layer 0 is sliding (config `local_layer_ids` contains 0) and a block boundary (0 mod 6 = 0), with no `attention_input` (`:861-862`). Following `Inkling2LoopSlidingDecoderLayer.forward` (`:876-911`): a = `attn_norm`(x); attention by `Inkling2LoopSlidingAttention` (`:546-637`): q = Wq a, per head x `q_l2_clip.scale`, L2 clip at 22.627416997969522 (`:190-202`, threshold from config default `qk_l2_clip_threshold`, `configuration_inkling2_loop.py:130`); k = Wk a, short conv (`:329-393`: depthwise causal conv of 4 taps, zero history, out[t] = sum_i w[i] x[t-3+i], then (out + x)/sqrt(5)), per KV head L2 clip at 22.627... with no scale (`:176-187`); v = Wv a, the same conv, per head unweighted RMS norm eps 1e-6 (`:67-76`); relative bias (`:239-270`): r = Wr a per head (16), x `rel_l2_clip.scale`, L2 clip at 8.0, r @ proj (16 x 1,024), gathered at distance i - j, 0 outside [0, 1,024); sink logit per head = `attn_sink_proj` a (`:620`); scores q.k / sqrt(128) + bias, causal (window 1,024), softmax over the scores and the sink, sink dropped (`:116-140`); GQA 24/8 (head h reads KV head floor(h/3), `:98-107`); o x sigmoid(`gate_attn` a), then `wo_ud` (`:531-543`); then `attn_sconv` short conv with residual /sqrt(5) (`:899`). Block boundary: block_states = [x], the stream is reset to h = the conv output (`:901-904`). `mlp_input` (`:828-853`): states [x, h], each unweighted-RMS-normed (eps 1e-6), one learned query (`attn_res.mlp_queries.0`, F32), softmax over the two with scaling 2304^-0.5, output = weighted sum of the normed states; then `mlp_norm` (gain, eps 1e-6) gives m_float. ## The 4-bit decode (pinned now, before any fetch)
From the PR's `Inkling2LoopDequantizeExperts` (core_model_loading patch, lines 772-818) and the quantisation config (`nvfp4_e2m1`, block 16, scale `float8_e4m3fn`, `amax_denominator`):
- `w13_weight` U8 [128, 2304, 1152] and `w2_weight` U8 [128, 2304, 576]: two E2M1 codes per byte, the even element in the low nibble, the odd element in the high nibble. Code -> value: 0, 0.5, 1, 1.5, 2, 3, 4, 6 for 0..7 and the negatives (with -0) for 8..15.
- `*_weight_scale` F8_E4M3 [128, rows, cols/16]: one scale per 16 consecutive decoded values of a row, decoded as float8 e4m3fn (bias 7, subnormals, code 0x7F / 0xFF = NaN).
- value = e2m1 x block_scale x (amax[e] / outer_scale_denominator), per expert e.
- Rows: w13 decodes to [128, 2304, 2304]; the converter then applies `Interleave(dim=1)` (`core_model_loading.py:232-251` at `6173a2f6`), which maps new row j x 1152 + i to stored row 2 i + j, and `_apply_gate` takes `chunk(2)` (`modeling:809-811`): **gate = stored even rows, up = stored odd rows**, each [1152 x 2304]; w2 decodes to down [2304 x 1152]. `F.linear` means out = W x.
- Checks before any metric (they do not use the metric): D1 shapes and block counts (cols x 2 / 16 = scale cols) for both tensors; D2 no NaN scale code and no negative scale in all 128 experts; D3 for every expert, max |decoded| / amax[e] lies in [0.25, 4] (the scale is named `amax`), reported per expert; D4 outer_scale_denominator recorded. If D1 to D3 do not all hold, the decode is not defended: stop, no metric, that is the result (third outcome of the issue).

## The integer lowering (both bars use exactly this)
Notation from `docs/model.md` section 1: rq(a, k) = floor((a + 2^(k-1)) / 2^k); RNE = round half to even. A shift k <= 0 is an exact multiplication by 2^-k (recorded).
1. **Weights** (section 11.4, `wb_int.py`): the mlp_norm gain g is folded into the matrices that read m, pi = RN32(g_k v) (c_0 = 1, because the norm itself is not lowered, see 2). One exponent per tensor, the largest e with RNE(2^e mx) <= 4,095, mx over the whole tensor and **all 128 experts together**: tensors Wr (router, 128 x 2304), Wg (all experts' gate halves), Wu (all up halves), Wd (all down). w = RNE(2^e pi). |w| <= 4,095 holds by construction, so the fraction outside 13 bits is 0 by construction (reported, checked); the fraction of non-zero decoded weights that become 0 is reported.
2. **m** (the boundary, as PR #138 / `20261112-132`): the norm stays float64. u = m_float without the gain (x_mlpin / rms); m = clamp(RNE(2^Em u); 2,047), Em = the largest integer E <= 9 with mx_u 2^E <= 2,047, mx_u = max |u| over all registered tokens (`scales/README.md` "The exponent of each cell" step 1, in-sample as `20261113-176`; 9 = 14 - t with t = 5 for d = 2,304, step 2's cap). In-sample fitting favours the integer arm; said in RESULTS.
3. **Router** (section 7 step 1, unchanged): lw = rq((m Wr)[e], kr) with kr = Em + e(Wr) - 8 (logit exponent 8, `scales/README.md` "The fixed exponents"); ly = floor(lw/8), l3 = lw mod 8, lr = 8 clamp(ly; 2,047) + l3. Score s_e = Sig[lr_e] (section 4 table 4, output scale 2^16, read at -16,384..16,383). Bias b_int = RNE(2^16 b_e) (b = `mlp.gate.bias`, F32). Choice: the 8 largest s_e + b_int, ties to the lowest index (section 1's argmax convention, applied 8 times). Float reference: logits = Wr' m_float, s = sigmoid, top-8 of s + b, ties to the lowest index (the reference's `torch.topk` tie order is unspecified, `:1169`).
4. **Routing weights (new relation, an existing form):** S = sum of the 8 selected s_e; w_e = floor((2 x 8 x 2^13 s_e + S) / (2 S)), i.e. 8 s_e / S at scale 2^13, by the rounded division of section 6 step 4. Scale 2^13 makes the largest weight 8 x 2^13 = 2^16, the bound of main's routing scale sc (Sig <= 2^16). Float: w = 8 s / (S + 1e-20) (`:1170-1172`).
5. **Expert hidden units** (section 7 "a block of hidden units", gate part unchanged): gw = rq((m Wg_e)[j], kg), kg = Em + e(Wg) - 8 (key exponent eg = 8); g0 = low8(gw), gh = (gw - g0)/256, gc = clamp(gh; 127), keyA = 256 gc + g0. **The up value is formed the same way** as a key: uw = rq((m Wu_e)[j], ku), ku = Em + e(Wu) - 8, keyB from uw as keyA from gw. (Main keeps u as a raw 16-bit factor; Inkling's up passes a soft cap, so it needs a table and a key.)
6. **Two new tables, format of Ts** (section 4 table 3: keys c = -32,768..32,767, c' = min(max(c, -64 x 2^8), 64 x 2^8 - 1), z = c'/2^8, entry = clamp(rha(2^E f(z)); 4,095)):
   - TA, f(z) = 4 tanh(z/4) / (1 + exp(-z)) (the gate factor of `:768-771`, `gate_softcap` 4.0);
   - TB, f(z) = 25 tanh(z/25) (`up_softcap` 25.0).
   Output exponent E by the rule that gives Ts its 2^6: the largest E with sup |f| on [-64, 64) x 2^E <= smax = 4,095 (Ts: sup 64, E = 6). TA: sup < 4, **E_A = 9**. TB: sup 25 tanh(64/25) < 25, **E_B = 7**. Step 2^-8, domain [-64, 64), saturating, as Ts. Chosen now, not tuned.
7. **Down, per expert** (section 7 dense form, one shift after down): y_e[k] = rq(sum_j TA[keyA_j] TB[keyB_j] Wd_e[k][j], kd), kd = (E_A + E_B) + e(Wd) - 12: y_e at 2^12 (F = 12, the stream scale of `20261112-132`), not clamped (section 6 step 5, section 7).
8. **Weighted sum (new, the routing-weight form):** out[k] = rq(sum over the 8 selected e of w_e y_e[k], 13), at 2^12. Block output of the integer arm = out / 2^12 (float64). Float: sum_e w_e (Wd_e (4 tanh(g/4) sigmoid(g) 25 tanh(u/25))), g = Wg_e m_float, u = Wu_e m_float, from the float64 decoded weights (with the gain applied).
Integer products are computed as float64 BLAS on integer-valued arrays; the code asserts every partial sum bound < 2^53 before each product (bounds: m-products 2^34.2, down 2^45, weighted sum 2^16 x max|y| x 8) and raises otherwise (a guard error = FAIL of the prompt).

## Metric
Per prompt and pooled over all tokens (n_tokens recorded):
- **rel_y** = ||out_int - out_float||_F / ||out_float||_F over all tokens and 2,304 channels of the prompt; per-token rel (median, p99, max) descriptive.
- **set_diff** = fraction of tokens whose integer set of 8 differs from the float set; for each such token the float score gap between the 8th and 9th choice (s + b), and the integer gap.
- **domain/clamp fractions per site**, with denominators: m clamp (|RNE| > 2,047, 0 by construction), router ly clamp (|ly| > 2,047; section 9 condition 5), gate gh clamp (|gh| > 127) and condition 6 (gh outside -16,384..16,383), up keyB the same, TA and TB domain exits (key outside [-16,384, 16,384)), condition 7 on uw (outside -32,768..32,767), Sig read outside -16,384..16,383.
- **weights**: fraction outside 13 bits (0 by construction), fraction of non-zero decoded weights rounding to 0, the four exponents.
- Descriptive, no bar: rel_y restricted to tokens where the sets agree; rel_y of an arm that uses the float set of 8 and float weights with the integer expert arithmetic (attribution of routing flips).

## Acceptance threshold
Bars taken from merged Qwen experiments:
- **B1 (block output)**: median over the 10 prompts of rel_y <= 1e-2 and max over the 10 prompts <= 5e-2. Source: the A2 bar of `experiments/20261109-8-qwen-real-weights/PREREG.md` (median rel_y <= 1e-2, max <= 5e-2), applied per layer in `experiments/20261113-176-qwen-int-attn/PREREG.md`. Qwen's unit is a (prompt, head) pair; a routed MLP has no heads, so the unit here is the prompt (10 values instead of 480). Nearest honest equivalent, said in RESULTS.
- **B2 (routing)**: pooled set_diff <= 1% (the same top-8 set on >= 99% of tokens). Source: the >= 99% top-1 agreement bar of `20261111-8-qwen-e2e-agreement` reused in `20261112-132-int-mlp-e2e` (PR #173, 97.40% against 99%). Qwen is dense and has no router; this carries the 99% discrete-choice bar over to the only discrete choice in this block. It does not carry over as a like-for-like number.
- **B3 (range verdict, separate, as `20261112-132`)**: IN-BOUND iff every domain/clamp count above is 0; otherwise OUT-OF-BOUND with the counts. Reported, not part of PASS.
- Determinism: the whole run twice, separate processes; every integer array's sha256 equal, else no PASS.
- **Outcomes registered.** PASS (B1 and B2): the MLP block meets bars Qwen's MLP did not (issue: Inkling moves ahead; next its attention block). FAIL of either: reported with which bar, the margin and the attribution arm (issue: Qwen stays first if the miss is like Qwen's or worse). DECODE NOT DEFENDED (D1-D3 fail) or REFERENCE NOT PINNED: the result, no metric.
