## Hypothesis
For the D8/F12/C2 synthetic DeltaNet research prototype, moving the boundary-state binding inside the arithmetic proof (each window proof opens an in-field sponge commitment of its incoming state/history and outputs one for its outgoing state/history) lets a verifier that holds only the statement descriptor and the previous window's output commitment accept an honest multi-window chain, while every named negative below is rejected, and no window verifier ever reads a boundary state in the clear.

## Metric
Per window proof: Boolean acceptance by a standalone verifier process that reads only its statement file and the proof file. Per chain: Boolean acceptance by a chain verifier that reads only the chain descriptor (F, D, C, chunk policy, window length, window count N, request, layer, model/weights label, initial root R0, public per-window token inputs, pre-conv inputs and outputs) plus the prover's list of (claimed output commitment, proof). Diagnostic: violated affine relations per relation group (recurrence, descriptor, history, commit-in, commit-out). Counts: core product columns, aligned columns, affine relations, range cells per window, from a committed counting script, compared with the built relation at D8. Timings: prove and verify wall-clock seconds per honest window proof (shared host, descriptive only, no performance claim).

Binding (fixed now): a Poseidon-shaped permutation over Goldilocks, width 12, rate 8, capacity 4, S-box x^7, 8 full + 22 partial rounds (the round shape Plonky2 uses), with this lane's own round constants (SHA-256 counter) and a Cauchy MDS matrix. This is NOT the vetted Plonky2 parameter set and no hash-security level is claimed. Commitment of boundary b: capacity initialised from SHA-256 of a public context (domain tag, F, D, C, request, layer, policy, N, b, model label, weights label), computed natively by the verifier; then absorb, in-circuit, the D*D state words, 9*D history words, one salt word, and fixed padding; output the first 4 lanes. R0 = commitment of boundary 0 replaces the public SHA-256 root and its public opening. Each S-box is 4 product columns; each partial round materialises 11 linear lanes. Window k proves: hash(ctx(k), S_in, H_in, salt_in) = C_in, the C-token recurrence from S_in, H_out = shift of H_in by the public pre-conv inputs, hash(ctx(k+1), S_out, H_out, salt_out) = C_out, descriptor cells pinned, and S_in range cells. The proof system has deterministic research coins and is not zero-knowledge: "not in the clear" means the verifier is never given the state, not that the proof hides it.

## Prior art
IVC and folding (Nova, ProtoStar, HyperNova) carry a running instance across steps; the step verifier sees only a commitment to the accumulated state. Recursive STARK continuations (RISC Zero segment receipts, SP1 shard joining) chain segments through committed pre/post memory images (Merkle or Poseidon roots) checked inside each segment proof and joined by a recursion or aggregation layer. zkLLM and similar zkML systems commit to KV caches or activations with polynomial or hash commitments. Plonky2 popularised Poseidon over Goldilocks with width 12, 8+22 rounds. Merged #98 (`qwen-joint-handoff`) linked two chunks inside ONE joint proof and kept the initial SHA-256 root with a public opening checked outside the arithmetic. New here: separately verifiable window proofs for the DeltaNet prototype whose boundary state is never public, with the initial root itself an in-field commitment opened inside the proof. Not new: there is no recursion or aggregation, the chain verifier runs N proof verifiers, and the sponge parameters are unvetted.
