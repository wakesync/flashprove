## Why
PR #178 ran upstream's integer attention on all 16 full-attention layers of abliterated Qwen3.8-27B and found zero clamping, but its scales were fitted on the same 1,461 tokens the error was measured on (its RESULTS section 7: "Out-of-sample scales ... not measured"). A deployed integer attention fixes its scales before it sees a prompt. This experiment freezes PR #178's per-layer exponents and measures, on eight new prompts that were never used to fit anything, whether the ranges still hold (no clamping) and whether the per-head error still meets (or misses) the same bar. These are new evaluation examples, not a retroactive split of PR #178's observed metrics.

## Hypothesis
Two axes per arm, each falsifiable independently, on the abliterated checkpoint's 16 full-attention layers and the eight held-out prompts, with the frozen PR #178 exponents:
- **H_R (range transfer).** Zero q, k and v entries clamped (|RNE| > CL) on every layer and prompt, and zero failures of the existing arithmetic guards (wide value |RNE| > 32,767; a score or accumulator array that is not integer-valued or not below 2^52). Falsified by one clamped entry or one guard failure anywhere.
- **H_F (fidelity).** Every one of the 16 layers has median per-head rel_y <= 0.01 and max <= 0.05 over its 8 prompts x 24 query heads = 192 cells. Falsified by one failing layer.
A range PASS with a fidelity FAIL, or the converse, is reported as such. Either FAIL is a valid result.

## Metric
Per (arm, layer, prompt, head h in 0..23), Frobenius over the prompt's tokens x 256 dims, with o_float the float64 softmax head output before the gate (PR #178's `float_o`): **rel_y** = ||o_arm[h] - o_float[h]|| / ||o_float[h]||. Every cell is reported, including cells on layers or prompts with clamping.
Counts, all with denominators (entries = tokens x heads x 256), per (arm, layer, prompt) and per (arm, layer), and with location: number of q, k, v entries with |RNE| > CL, and per (arm, layer, prompt, head or kv head) the count of clamped entries wherever it is non-zero; max |RNE| of q, k, v and its ratio to CL (headroom, descriptive); guard failures per guard; max |s| against Smax = 256 CL^2; count of e = 0 table entries (descriptive).
Descriptive, no bar: rel of the attention contribution after the float gate and o_proj, ||mix_arm - mix_float|| / ||mix_float||, per (arm, layer, prompt); observed maxima |q / 16|, |k|, |v| per layer on the held-out prompts (recorded, never used to set a scale); per-layer seconds; peak RSS of the process and of the process tree.
Units: memory in decimal GB computed as kB x 1,024 / 10^9 from /proc (PR #178 divided kB by 10^6; fixed in this experiment's copy of the watchdog); disk in decimal GB (bytes / 10^9).

## Acceptance threshold
Per arm, independently:
- **H_R PASS** iff the run completes all 16 layers, every clamp count is 0 and every guard count is 0. FAIL if any clamp or guard failure is recorded on any completed layer (a partial run with one is FAIL; without one it is NOT TESTED on the missing layers).
- **H_F PASS** iff all 16 layers pass (median <= 0.01 and max <= 0.05 over their 192 cells) and no arithmetic guard failed on that arm. A true arithmetic guard failure makes that arm FAIL / non-evaluable on H_F as registered; the prompt is never excluded. FAIL if any completed layer fails.
- Both axes require V1, V2 and V3 to hold; otherwise that arm's verdicts are "comparison invalid".
The bar is PR #88's A2 per-head rel_y bar, unchanged, as used in PR #178.

## Runs
Deterministic float64 and integer arithmetic, no seeds. A repeat gives identical numbers, so there are **no reruns for variance** (a deviation from the >= 5 runs standard, stated now as in PR #178): the registered result is each arm's two verdicts over all (prompt, layer, head) cells; the spread reported is over the 192 (prompt, head) cells per layer (median, min, max, counts over 0.01 and 0.05). Determinism is checked by V2.
- Heavy work only through the shared gate: `flock <bigmem lock> fp-heavy.sh taskset -c 8-13 /usr/bin/time -v ...`, 6 cores, BLAS threads 6 in the main process, 6 spawned DeltaNet head workers with 1 BLAS thread each. Host shared and loaded; recorded in ENV.json.
- No exclusions. Malformed, duplicate, missing or unexpected records make the summariser refuse (exit non-zero, nothing written), as PR #178's amended summariser does.
- **Debug before the registered run (disclosed now).** New code is debugged only on synthetic arrays (numpy `default_rng(0)`) and on PR #88's fixture "The capital of Italy is" (5 tokens, not in either prompt set) through stock layers 0 to 3. Committed checks before the run: (a) with exponents fitted in-run on a synthetic input by `int_attn.fit`, the frozen-scale evaluator reproduces `int_attn.arm_prompt`'s integer o, de-scaled output and stats bit for bit; (b) changing an evaluation maximum (an outlier 100 x the frozen range in q, k or v) does not change any frozen exponent or sh, and the outlier is clamped and counted; (c) the table loader refuses a wrong hash, a missing, duplicate or extra (arm, layer) row, and a row with the wrong clamp; (d) the summariser refuses malformed, duplicate, missing and unexpected records; (e) on the fixture, the float split equals `q1_forward.attention` bit for bit at layer 3. ## Amendments

### A1, 2026-11-14 (after results; registered code changed after the run)
**What changed.** `summarise_heldout.py` now refuses (exit 2, nothing written) on malformed evidence that it previously accepted: a count that is not a non-negative integer (negative, float, JSON boolean, string) or exceeds its denominator; a `rel_y`, layer statistic or `mix_rel` that is not a finite non-negative number (NaN, Infinity, negative); an evidence flag (`det_bit_equal`, `mix_bit_equal_q1`, `range_pass`, `fid_pass`, `scales_frozen_ok`) that is not a JSON boolean; a prompt row whose `T` is not the frozen manifest's `n_tokens` for that prompt, or whose `q_n` / `k_n` / `v_n` is not T x 24 x 256 / T x 4 x 256 / T x 4 x 256; a layer row whose denominators are not 541 x 24 x 256 / 541 x 4 x 256 / 541 x 4 x 256; per-head clamp arrays (24 query heads, 4 kv heads) that do not sum to the row's count; and a non-zero count of entries over the clamp without a recorded max |RNE| over the clamp, or the converse. The verdict rules, bars, arms, scales and every other line of the summariser are unchanged.

**Why.** The independent review of PR #206 (https://github.com/wakesync/flashprove/pull/206#issuecomment-6874859970) showed, on temporary copies of the committed records, that the summariser accepted a negative clamp count that cancels a real clamp into an H_R PASS, NaN and negative `rel_y`, `T = 0` and the string `"false"` as a determinism flag. The "Runs" section above promises that malformed records make the summariser refuse. This amendment makes that promise hold for those cases. The reviewer also checked that the committed records contain none of these corruptions.

**Effect on the result: none.** On the committed run records the amended summariser writes `summary.json` and `summary.md` byte-identical to the committed files (sha256 4f4eef23765611d1ebf4459f7b908725c47a612a4c9209668f52d631d1cf2f81 and db20f58dc3a5c523c55c0dd3052ac3497eb327146581d8fa15d3c612a08ce8ba). No run, no model forward and no committed run file changed; no reported number changed; both arms still FAIL both axes.

**Tests.** `test_heldout.py` gains 21 synthetic tests (`FailClosed`) and 6 tests on a temporary copy of the committed records (`CommittedCopy`, a directory the test creates and removes; the committed files are only read), one per malformed case above, including each case the review names. 59 of 59 pass. ### A2, 2026-11-14 (after results; registered code changed after the run, second time)
**What changed.** Three changes to `summarise_heldout.py`, all in validation before the verdict block, which is unchanged.
1. *Guarded nulls are admitted where the evaluator writes them, and only there.* When an arithmetic assertion of PR #178's `int_attn` fires, `heldout.eval_frozen` writes the prompt row with `mix_rel`, `max_abs_s`, `e_zero` and `causal` all null and the assertion text in `guard_fail`, and `heldout.attention_layer` writes `rel_y` null for all 24 heads of that prompt. If every cell of a layer is guarded, the layer row carries NaN `rel_median` / `rel_max` / `rel_min`. A1 refused the null `mix_rel`, so a registered guard-failure outcome (H_R FAIL, H_F FAIL, prompt kept) could not be summarised. A2 admits exactly that representation: all four fields null together, a non-empty guard list of non-empty strings that is not only the wide-value guard, and exactly 24 null cells for that prompt. NaN layer statistics are admitted only when the layer has no valid cell. Any other null, a partial null set, a null without a guard, or a null cell on an unguarded prompt is refused.
2. *Every retained descriptive field is checked before anything is written.* `obs_mx_q/k/v`, `arm_seconds` and the timing seconds (`total_s`, `float_s`, `ref_attention_s`) must be finite and non-negative. `max_abs_s` must be finite, non-negative and at most Smax (on prompt rows also an integer). `causal` must equal 24 x T(T+1)/2, and `e_zero <= causal`. `wide_over_32767` must be non-zero exactly when the wide-value guard is recorded. A layer row's `q/k/v_maxw` and `obs_mx_*` must equal the maximum over its prompt rows, its `max_abs_s` the maximum over the non-null ones, and its `e_zero` / `causal` / `wide_over_32767` the sum. Its `n_pairs`, `n_cells_valid`, `rel_min`, `n_over_001` and `n_over_005` must equal those recomputed from its cells.
3. *Per-head counts are bounded by the head's capacity.* Each entry of `q_over_by_head`, `k_over_by_kvhead` and `v_over_by_kvhead` must be at most T x 256.

**Why.** The second independent review of PR #206 (https://github.com/wakesync/flashprove/pull/206#issuecomment-6875930332) showed two things on temporary copies of the committed records. First, A1 refused the evaluator's guard-failure representation: a constructed guard on C2047 / layer 3 / h02 was accepted as FAIL / FAIL at 27b057dd but refused at 2e7dc350. Second, A1 still accepted NaN `max_abs_s`, infinite or missing `obs_mx_q`, `arm_seconds = -1`, and 5,121 clamps in one head of a T = 20 prompt, whose capacity is 5,120. The reviewer stated that none of these is present in the committed data and that none turns the committed FAIL into a PASS.

**Effect on the result: none.** On the committed run records the amended summariser writes `summary.json` and `summary.md` byte-identical to the committed files (sha256 4f4eef23765611d1ebf4459f7b908725c47a612a4c9209668f52d631d1cf2f81 and db20f58dc3a5c523c55c0dd3052ac3497eb327146581d8fa15d3c612a08ce8ba). No run, no model forward and no committed run file changed. No reported number changed. Both arms still FAIL both axes.
