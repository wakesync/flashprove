## What this lane decides

This is a design lane. It does not build M2. It produces DESIGN.md (the M2 statement, lowering, sizing and verifier entry point) and four small CPU prototypes that test the design's load-bearing assumptions. The verdict is a GO / NO-GO for an M2 build lane, under the rule in "Acceptance threshold".

Registered design decisions (fixed now, before any prototype runs):
- **D1 scope.** "One full layer at exact shape" (FEASIBILITY.md M2) does not fit the research harness. The layer's matrices (in_proj_qkv 5,120 x 10,240, in_proj_z 5,120 x 6,144, in_proj_a/b 5,120 x 48, out_proj 6,144 x 5,120, SwiGLU 3 x 5,120 x 17,408) are about 3.8e8 MACs per token. As affine terms with public weights that is about 70x the whole M1b statement per token, and they are dense-family operators FlashProve already proves (docs/model.md sections 5 and 7). M2 is therefore **one V head of one Qwen DeltaNet layer, end to end from the in_proj outputs to the gated-norm output, at T = 16**, with the 48-head layer cost extrapolated from it (labelled as an extrapolation). The matmuls, pre-norm RMSNorm, residual and MLP stay unproved in M2.
- **D2 statement boundary.** Public: the head's in_proj outputs per token (pre-conv q, k, v channels of its K head and V head, 384 values; a_raw, b_raw scalars; z, 128 values), the conv kernels, A_log, dt_bias, gated-norm gain w, S0, the gated-norm output y (128 per token), and S_T. Private: every state S_t, M, delta, the head output o (private in M2, public in M1/M1b), and the gated-norm intermediates.
- **D3 which of gate / conv / norm M2 proves.** At this boundary, conv1d, SiLU, the q/k L2 norm, the q scale, the decay gate exp(-A softplus(a_raw + dt_bias)) and beta = sigmoid(b_raw) are functions of public integers only. The M2 verifier **recomputes them** from the public integers under the integer spec (DESIGN.md section 3), in O(D T) work, and uses the results only as relation targets and coefficients. They are not proved as in-relation gadgets in M2: proving them would add cost and no soundness. The **gated RMSNorm of o is proved** in-relation (it reads the private o). The in-relation gadget form of conv / SiLU / L2 norm / gates is needed only when the in_proj outputs become committed (M3); DESIGN.md gives its estimated cost, and an optional M2 arm (M2-R) may build it as a rehearsal.
- **D4 range sizing.** Every RNG range cell has an honest contract |x| < 2^18 and sits in a 16-column RNG matrix with window 2D = 2^23 (b0 = 12, b1 = 11), so an honest combination is at most 16 x 2^18 = 2^22 = D and RNG proves |x| < 2^23. Any class whose honest values can reach 2^18 is limb-split at 2^18 (as delta in M1b). Non-negative quantities that need an exact interval (floor remainders, isqrt residuals, divisor-minus-remainder) are not RNG cells; they are exact.
- **D5 remainders.** Two arms. Arm A: exact bit decomposition (as M1b). Arm B: lookup-exact remainders. Each F = 12 bit remainder is one product cell used as a direct LKP key into the 2^12 range table (LkpTablePart with empty rows); a 2F = 24 bit remainder is two such limbs plus one recombination relation. The keys are read from product row a through a LaidBlock region, like RNG's cells.
- **D6 verifier entry point.** The M2 verifier takes the shape (T, D, F, head constants) and the public inputs as canonical 64-bit field words. It decodes each word itself (word < p; signed value within its class bound; a and beta derived, not supplied), derives every relation target and coefficient from the decoded integers, sizes the run, and then runs the proof verifier. There is no separate `admissible()` that a caller can skip, and there is no entry point that accepts caller-built relations.

## Hypothesis
The registered M2 design (one head, T = 16, F = 12, two-limb delta, private o, proved gated RMSNorm, verifier-recomputed gates / conv / SiLU / L2 norm, verifier-side admission) is buildable on the merged M1b machinery within the research harness. Concretely: (H1) a counting model of the lowering reproduces M1 and M1b exactly; (H2) lookup-exact remainders cut product columns and relations per state cell per token by at least half; (H3) the M2 head statement at T = 16 fits a product table of at most 2^22 under arm B; (H4) every proposed range-cell class and exact limb stays inside its contract on the realistic suite; (H5) a verifier entry point that admits its own integer public inputs rejects every hostile public encoding on its own, including the #63 review's R9 statement that the current caller-side path accepts.

## Metric
- **H1.** Counting model `count_model.py`: for a lowering spec (D, T, F, arm, gadgets) it returns product columns used, aligned layout length, table log-length, linear relations, relation terms, range cells, RNG cell rows and digit entries, LKP keys. Compared to the measured M1 (#47: 2,338,816 product columns, 4,761,088 relations, 11,430,400 terms, log-length 22) and M1b (#63: 1,141,248 columns, 2,231,808 relations, 5,174,272 terms, 67,072 range cells, log-length 21) from their evidence files.
- **H2.** From the model at the M1b shape (D = 128, T = 4): product columns per state cell per token, relations and terms, arm A vs arm B; ratio (B / A).
- **H3.** From the model: the M2 head statement at T = 16, arm A and arm B: product columns, layout length, log-length, relations, terms, range cells, LKP keys. Also the largest T that fits log-length 22 per arm, and the 48-head layer extrapolation per token.
- **H4.** `head_reference.py`: an integer reference of the whole head (conv1d kernel 4 with causal zero padding, SiLU via sigmoid table, L2 norm with eps, q scale, decay and beta tables, staged-floor recurrence, gated RMSNorm) at D = 128 with synthetic init (conv kernels U(-0.5, 0.5); A = U(1, 16); dt as M1; w = 1; pre-conv inputs R1..R4 as M1, z ~ N(0, 1), a_raw, b_raw ~ N(0, 1)). Per run: the maximum |x| of every RNG cell class (S', M, delta_lo, delta_hi, o, n) and the maximum of every exact limb class (remainders, sigma_o, isqrt residuals, sigma - 1 - r), and the worst float64 divergence of S and y. Suite: R1..R4 x seeds 1..5 x 1,024 steps = 20 runs.
- **H5.** Prototype `research/operators/qwen_deltanet_m2/admit_proto.cpp` on the M1b statement (D = 128, T = 4, merged lookup.h unchanged): entry `verify_from_words(words, proof)` vs the current caller path (`admissible()` in main, then `lookup_verify` with caller-built relations). Per honest seed: accept, decode+derive seconds, verify seconds. Per hostile statement: accept / reject and which stage rejected (decode, or the proof verifier).

## Acceptance threshold
GO for an M2 build lane only if all hold:
- H1: the model's columns used, relations, terms and range cells equal the measured M1 and M1b values exactly (4 + 4 numbers; log-length too).
- H2: at the M1b shape, arm B / arm A <= 0.5 for product columns per state cell per token AND for relations.
- H3: arm B, one head, T = 16: table log-length <= 22. (Arm A at T = 16 is descriptive; its largest fitting T is reported.)
- H4: in 20/20 runs every RNG cell class has max |x| < 2^18 after the registered limb splits (D4: delta split at 2^18; any other class that reaches 2^18 FAILS H4 unless DESIGN.md registered its split before this run), and every exact limb is in [0, 2^12).
- H5: (a) 10/10 honest seeds accepted by `verify_from_words`; (b) 100% of hostile public encodings rejected by `verify_from_words` alone, at least: for each of the 8 public classes (S0, a, beta, k, v, q, o, S_T) one element set to (p + 1) / 2 and one to its class bound (bound + 1 for one-sided classes), one non-canonical word (honest value + p), one header mismatch, and R9 (o_T[j] replaced by o_T[j] - 2^-F mod p with a fresh hostile proof whose remainder absorbs the shift); (c) control: the same R9 statement and proof are ACCEPTED by the current caller path with `admissible()` skipped (shows the hole is real and the new entry closes it).
Anything else is NO-GO, with the failing item named. A NO-GO that names a smaller buildable scope (e.g. T = 8 arm A) is reported as such.

## Runs
- H1 to H3: deterministic counts, n = 1 each (no variance by construction).
- H4: 20 runs (R1..R4 x seeds 1..5), 1,024 steps each, integer reference, CPU.
- H5: honest seeds 1..10 (M1 fixture recipe), one process each, sequential, pinned to 6 cores (taskset -c 0-5); n = 10, median, SD, min/max for decode+derive and verify seconds. Hostile statements: seed 1, one process. Exclusions only for host faults, rerun and reported. Shared loaded VM, timings indicative only.
