## Deviations from the registration
1. **The run is partial. It stopped itself on the registered free-disk floor.** After layer 51 the host's free disk read 20.9 GB, under the lane's 21 GB floor, and the run loop ended the job (`runs/progress.log.jsonl`, last line; `runs/progress.log`, `end rc=4`). The 00:05Z hard stop was not reached. The disk loss is outside this lane (its scratch holds one 28 MB state file) and its cause is not established here. The lane did not resume: the floor is a registered stop rule and the disk was still under it. Layers 52 to 63 have no baseline and no arm rows. Under the registration a partial run has no all-layer verdict.
2. **Reduced layer set (A-1, before the run).** The arms were to run on R33 (33 layers), not on all 64, by the timing rule written in A-1 and applied by `decide_set.py` (projected 4,460 s for 64 layers against 2,792 s available; `runs/progress.log`). With the stop of item 1 the arms ran on the 27 members of R33 up to layer 51. The 6 members above it (52, 55, 56, 59, 60, 63) were not run.
3. **Fixture and registered run as one queued job (A-1).** The lane stopped its first fixture debug itself when the free disk first fell under the floor, and withdrew a second attempt after 8 minutes in the heavy-slot queue. The third ran as the first step of the same job as the registered run (`run_all.sh`); the registered run started only after the fixture reported ok (`runs/debug/fixture-2.json`).
4. **Debug outputs were seen before the registered run (A-1).** The fixture's per-arm numbers on the fixture tokens (stock layers 0 to 3, 5 tokens, not in the suite) were read while checking the code. They are committed under `runs/debug/` and are not results. They did not enter the layer-set rule, which reads timing only.
5. **A-2 was written during the registered run**, before the lane read any arm or baseline number of it: arm W's class is also checked on every baseline layer. It can only make arm W's class verdict stricter. On this one point arm W's class reading is not pre-registered in the strict sense; both counts are reported.
6. **Disk floor unit (A-1).** Checked in decimal GB.
7. **Wording.** The PREREG says the arm W ledger count "counts the 12-bit limbs a value of each class needs". `ledger_w.py` counts lookup keys per committed cell, by the pattern `bounds.py` uses for its one class wider than 12 bits. It is the same count under the design's name for it.

## What is not established
- **No registered verdict.** The run is partial, so no arm has an all-layer verdict and H is formally undecided. Section 2 says what the layers done already settle; that is arithmetic on the registered rule, not a verdict.
- **Nothing about layers 52 to 63.** Not the baseline, not any arm.
- **Nothing about the arms on the 25 layers up to 51 that are outside R33**, beyond their baseline class counts.
- **Nothing about tokens.** The run is open loop and has no logits. Whether any arm keeps the model's top-1 tokens, and how per-layer error compounds across layers, is not measured here. A per-layer error over or under the bar does not say what the tokens do.
- **Class counts are observed maxima, not bounds.** They hold for six prompts (672 tokens) on the abliterated checkpoint. Another prompt can exceed them. Nothing here is about the stock checkpoint beyond layer 16.
- **No proof, relation or verifier was built or changed.** The arms are numerical lowerings. Arm W's ledger cost is counted from `bounds.py`, not built.
- **Not a fully integer layer.** The DeltaNet heads, attention, the q/k norms, in_proj and out_proj were float64 in every arm. An arm's error here is the error of the norm-output arithmetic plus PR #138's integer MLP.
- **Not replicated.** One deterministic run on a shared, loaded host. Every number is measured, unreplicated.
- **The design choice.** This lane reports. It does not choose the arithmetic.
