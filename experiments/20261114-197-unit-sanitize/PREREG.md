# PREREG: 20261114-197-unit-sanitize

Issue: #197 (part of #182 and #156). Lane: ubsan197. Date (UTC): 2026-11-14T03:30Z. Base commit: bf447d2725acbb185f21cd2397edde46c38f095c.

## Hypothesis
`prover/tests/unit.sh` can take an opt-in `--sanitize` switch for host (.cpp) builds that leaves its default compile line, its output-directory checks and every default binary unchanged, and the reader-parity cases of #182, built that way, give the same categories as the release series with no sanitizer report.

## Metric
All outcomes are deterministic functional outcomes, not timings.

1. **Harness controls.** Through `unit.sh --sanitize`: (a) a host program with a signed `int` overflow and (b) a host program that reads one element past the end of a heap array, each hidden from the compiler with `volatile`. Recorded: unit.sh's exit status and whether `<test>.log` contains the sanitizer's text (`runtime error: signed integer overflow` for (a), `ERROR: AddressSanitizer: heap-buffer-overflow` for (b)). The same two sources are also built and run once without `--sanitize`, for information only (expected: exit 0, no sanitizer text). (c) `--sanitize` with a `.cu` source: exit status and message (expected 2, usage error, nothing built). (d) The "not run" path: `unit.sh --sanitize build` with a `PATH` whose first `g++` is a private wrapper that fails whenever its arguments contain `-fsanitize` and otherwise runs the real `g++`; expected exit 77 and a line starting `not run: `.
2. **Default-build identity.** `parameter_file_tables_test.cpp`, `parameter_file_one_bits_test.cpp` and `parameter_file_one_place_test.cpp` are built with the base commit's `unit.sh` (from `git show <base>:prover/tests/unit.sh`, placed temporarily beside it in `prover/tests/` so that it runs from the same checkout) and with the patched `unit.sh`, each under `bash -x`, into separate private directories. Recorded: SHA-256 of each binary, and the traced `g++` command line with the output directory replaced by a placeholder. Also: `python3 -B tests/folder_look_copies_test.py` (the agreed text of `open_above()`) at the patched head.
3. **Fixture identity.** The 33 synthetic reader fixtures (plus `dense-base/policy.txt`) are regenerated by the fixture code of `experiments/20261113-182-reader-parity/reader182b_supplement.py`, copied unchanged into this experiment's runner, and every regenerated file's SHA-256 is compared with `runs/supplementary-matrix/fixture-hashes.json`. Files that need a verifier build to regenerate (`dense-base/arrays.txt` and the dense `layout.txt` files, made by `cp_verify -plan arrays` and `pack_layout.py`) are not regenerated; the reader does not read them. Count: files compared, files equal.
4. **The registered #182 UBSan arms.** Baseline reader (the base header of #182, `git show 59bff9a4608e0cc720d58d7c30823a8838fa43e4:prover/common/parameter_file.h`, beside copies of the three test sources whose one include is changed, as in the #182 README) and patched reader (current sources), each built with `unit.sh --sanitize build` into its own private directory. Each sanitized `parameter_file_tables_test` runs on each of the 33 committed supplementary fixture `policy.txt` files (used only if item 3 found every regenerated file equal), five repetitions. Per call: exit status, the reader category parsed exactly as `reader_tag()` in `reader182b_supplement.py` does, and whether a sanitizer reported (exit 97, or standard error containing `runtime error:` or `AddressSanitizer` or `LeakSanitizer`). The release category for the same case and arm is the `observed` value in `runs/supplementary-matrix/01-<case>-<arm>.json` (all five release repetitions agree). Counted per repetition: category mismatches against release, mismatches against `expectations.json`, sanitizer reports.
5. **Positive controls.** `parameter_file_one_bits_test` and `parameter_file_one_place_test`, both arms, sanitized, via `unit.sh --sanitize run <source> <dir> tests/configurations/pinned_no_proof_of_work/policy.txt` (the argument the #182 supplementary series passed): unit.sh exit and whether the log has sanitizer text.

## Acceptance threshold
PASS requires all of:
- Both negative controls reported: unit.sh exit 1 and the named sanitizer text in the log. `.cu` with `--sanitize`: exit 2. Wrapper path: exit 77 with a `not run: ` line.
- All three default binaries byte-identical between the base and the patched `unit.sh`; if any differ, PASS on this item still holds only if the traced `g++` command lines are identical and a rebuild with the base script shows the same difference (non-reproducible toolchain). `folder_look_copies_test.py` exits 0.
- Every regenerated fixture file equals its committed hash.
- UBSan arms: 0 category mismatches against release and 0 sanitizer reports in each of the five repetitions (330 calls).
- All four positive-control invocations pass (`<test>: passes`, exit 0) with no sanitizer text.
The flag set is fixed now, copied from `verifier/tests/sanitized_walk_test.sh`: `-O1 -g -fno-ipa-modref -D_GLIBCXX_ASSERTIONS -fno-omit-frame-pointer -fsanitize=address,undefined -fno-sanitize-recover=all -std=c++17 -pthread`. To these `unit.sh` adds only what its default host line already passes for the source to build: `-DDIGEST_WORDS=$dw -DBLK_FIELD=$field`, the `--slot-count` define when given, `-msha -msse4.1 -mssse3 -I. -I../blocks`. Warning flags are left out, as in `sanitized_walk_test.sh`. Runtime settings are linked in as in `sanitized_walk_test.sh` (`detect_leaks=0:exitcode=97:handle_abort=1:max_allocation_size_mb=8192:hard_rss_limit_mb=12288` for the address sanitizer, `print_stacktrace=1:exitcode=97` for the undefined-behaviour sanitizer) but without `log_path`, so a report goes to standard error and therefore into `<test>.log`.

## Kill criterion
- A sanitizer report on any reader case or positive control: stop the series, keep the receipts, report the case and the trace, verdict FAIL for that arm. No reader or verifier source is patched in this lane.
- A UBSan category that differs from release: report it (the release result then depended on undefined behaviour), verdict FAIL.
- A negative control not reported, or the default line not provably unchanged: the harness change fails; the UBSan arms are not run on it; verdict FAIL or PARTIAL with the reason.
- A regenerated fixture hash that differs: the UBSan arms are not run; PARTIAL.
- Budgets: registered run budget 30 minutes elapsed from the moment `fp-heavy.sh` grants the slot (logged), hard stop for the lane 2026-11-14T05:30:00Z. Neither moves after registration. Cores 10-11 only (`taskset -c 10,11`), at most two parallel compiler or test processes. Release builds and release runs: 4 GiB address-space cap. Sanitized runs cannot take an address-space cap (the address sanitizer reserves terabytes of virtual address space); they are bounded by `RLIMIT_CPU` 115 s soft / 120 s hard per process, a 150 s wall timeout per call, `ASAN_OPTIONS=hard_rss_limit_mb=2048:max_allocation_size_mb=2048` in the runner's environment (overriding the linked-in larger bounds for this experiment only), and the shared heavy-job gate for the whole batch. Sanitized builds (the compiler itself is not sanitized) keep the 4 GiB cap. No weights, model, GPU, prover, serving route or spend.

## Runs
- Harness controls (items 1, 2, 5): one invocation each; they are deterministic pass/fail checks, not samples.
- UBSan arms (item 4): five repetitions over the 33 cases in stable lexical order, before/after ordering alternating by repetition (odd: before first), as in the #182 series. No warmup. No completed call is excluded. Summary per repetition of category mismatches and sanitizer reports: median, population SD, min, max over n = 5.
- Seeds: none (deterministic byte mutations, fixed fixtures).
- Debug executions before the registered run use only a throwaway program in the private build directory (not one of the two negative-control sources, not a positive control, not a fixture) and the `.cu` refusal on an existing `.cu` source. Compile-only checks of the registered sources are allowed. The runner itself is exercised first in a dry mode that builds nothing and runs no registered program.
- Outputs: harness receipts under `experiments/20261114-197-unit-sanitize/runs/`; the UBSan arm receipts in a new sibling directory `experiments/20261113-182-reader-parity/runs-ubsan-20261114/`; an append-only addendum section in that experiment's `RESULTS.md`. No committed file of #182 is otherwise edited.

## Prior art
The flag set, its compiler probe and its four negative controls exist in `verifier/tests/sanitized_walk_test.sh` (repository, since the initial public release); this work reuses them for the prover's host unit harness rather than inventing a new set. AddressSanitizer and UndefinedBehaviorSanitizer (Serebryany et al., USENIX ATC 2012; the GCC/LLVM sanitizer runtimes) are the standard tools; fuzzing-plus-sanitizer harnesses for parsers (OSS-Fuzz, libFuzzer) motivate running a strict file reader's malformed corpus under them. zkML systems (EZKL, zkLLM, Jolt, Expander) and TEE work (H100 CC, TDX/SEV-SNP) are not involved: this is a host build option and a sanitizer re-run of an existing deterministic reader matrix, with no proof, circuit or attestation. What is new here is only the harness option and the sanitizer arm of #182's registered matrix.
