## Design (fixed now)

1. Pin file `experiments/20261112-149-leaf-v2/runs/registered-pins.json` (new file), generated by the committed script `experiments/20261114-203-leafv2-registered-pin/make_pins.py` from the committed files only, no timestamp. It lists, for `run1`, `run2`, `run3`, the SHA-256 of every file the readers consume that exists in that directory (`blocks.jsonl`, `run-meta.json`, `leaves-v2.json`), and the SHA-256 of the two committed compare files `summarise.py` consumes. Its note says: a committed list that binds "registered run" to what the repository holds, not authentication.
2. `wb_leafv2.py`: a function `check_registered(rundir)` and `compare_runs(a, b, registered=False)`. With `registered=True`, before any other read, each run directory must: not be a symlink; have a normalised base name that is a run in the pin; for each consumed name, be present as a regular file (not a symlink) exactly when the pin lists it, with an equal SHA-256. Otherwise `EvidenceError` (exit 2) with a message containing `registered pin`. The pin is always read from the committed path in the repository, never from the run directory or its parent. CLI: `wb_leafv2.py compare A B out.json --registered`. Without the flag, `compare` is byte for byte the behaviour on main.
3. `summarise.py --registered`: checks all three runs and both pinned compare files against the pin first (missing or different = refusal), then computes H3 as on main and adds `h3.overall.basis` = `single-run` (one of run 2 / run 3 alone has every block of the union in common with run 1) or `union`. Status: `FAIL` on any mismatch; `PASS` only with basis `single-run` and 78 of 78; `PASS-UNION` when the union reaches 78 and no single run does; `PASS-SUBSET` / `BELOW-COVERAGE` as on main. Writes `runs/summary-registered.json` (`--check` compares with it). Without the flag, output and exit codes are as on main.

- Default mode: the default code path keeps main's reads and main's output.
