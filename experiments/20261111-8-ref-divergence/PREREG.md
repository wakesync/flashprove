## Reference definitions (fixed now)
All three references start from the same float64 real-valued input (and taps), produced by the split generator.

- **FP64 reference (exact proxy).** float64 numpy, correctly rounded inputs (none: the input is already float64), libm transcendental functions, sequential left-to-right summation. Used as "exact math" for the envelope denominators.
- **BF16 reference.** Format bfloat16: 1 sign, 8 exponent, 7 stored mantissa bits, bias 127, subnormals kept, round to nearest, ties to even (RNE), applied directly from float64 (no double rounding through float32). Overflow: not reachable at these magnitudes (max finite 3.39e38); counted if it happens. Every op input (and conv tap) is rounded to BF16. Compute in FP32 (numpy float32 ufuncs, not correctly rounded transcendental functions), sequential left-to-right FP32 accumulation for conv sums and norm energies. Rotary cos/sin are computed in FP32 from FP32 inverse frequencies `theta^(-j/32)` and FP32 angle `pos * inv_freq`, then rounded to BF16 (the common pattern of casting the cos/sin cache to the activation dtype). Output rounded to BF16 (RNE).
- **FP8 reference.** Format OCP OFP8 E4M3 (the "E4M3FN" variant): 1 sign, 4 exponent, 3 mantissa bits, bias 7, subnormals kept (min subnormal 2^-9), max finite 448, no infinities, NaN only S.1111.111. Rounding RNE. Saturating conversion (OCP "saturation mode", satfinite): |v| > 448 maps to sign * 448 and is counted as an FP8 saturation. Scale granularity: one FP32 scale per (op, input role, F-independent) tensor role, i.e. per op for activations and separately for conv taps; **delayed scaling**: s = 448 / amax, where amax is the largest |input| over the whole calibration split of that op and role, computed once on calibration and frozen in a committed file before held-out evaluation. Quantize: q = E4M3(RNE, satfinite)(v * s); dequantize v' = q / s in FP32. Compute exactly as the BF16 arm (FP32 compute, sequential FP32 accumulation, BF16 cos/sin), output rounded to BF16. E5M2 is not studied (it is the gradient format in the OCP recipe); a future arm would need its own registration. This FP8 reference is a definition of one W8A8-style recipe, not a statement about any serving engine.
- BF16 and FP8 are separate arms with separate metrics and separate verdicts. Neither is used as a stand-in for the other.

## Integer pipeline conversion (pinned)
- Scale S = 2^F, F in {12, 14, 16}, fixed by the committed operator; nothing is fitted.
- Input conversion: X = RNE(x * S) (ties to even), then saturation to the operator's integer domain: [-S, S - 1] for conv inputs, taps, rotary and norm inputs; [-8S, 8S - 1] for the nonlinear scalar. Each clamp is counted as an integer range violation.
- Norm domain: if the quantized vector's key k falls outside [0, 4096) the committed relation has no witness. That vector is counted as an integer out-of-domain event and excluded from that op's error statistics (counts reported).
- Output dequantization: y / S, exact in float64.

## Splits (frozen by hash before evaluation)
Generated by a seeded generator committed in the second commit of this branch together with the split files and a manifest of their SHA-256 hashes. No evaluation code runs on any split before that commit is pushed.
- Calibration: seeds 1..5 (5 runs). Used only to set the FP8 delayed scales; its metrics are reported, labelled calibration.
- Held-out: seeds 1001..1005 (5 runs). The decision uses held-out only.
- Stress: seeds 2001..2005 (5 runs), wider distributions (3x the primary scale) to exercise integer clamps and FP8 saturation. Descriptive only, no threshold.
- Debug: seed 9001 only, kept under ignored `work/`, never committed as evidence, never one of the registered seeds.
Per run sizes: nonlinear 4096 scalars per function (one shared draw); conv 256 chunks (1024 outputs); l2 64 vectors (8192 outputs); rms 64 vectors (16384 outputs); rotary 64 vectors (4096 rotated coordinates, the 192 unrotated coordinates are identity in all arms and excluded).
Primary distributions (calibration and held-out): nonlinear x ~ N(0, 2^2) truncated to [-7.9, 7.9] by resampling; conv inputs and taps ~ N(0, 0.35^2) truncated to [-0.99, 0.99]; l2 and rms: per vector sigma ~ U(0.55, 0.65), entries N(0, sigma^2) truncated to [-0.99, 0.99], vectors resampled until the float mean square is in [0.27, 0.95]; rotary entries N(0, 0.35^2) truncated to [-0.99, 0.99], position uniform in [0, 1024). Stress: the same with 3x sigma and no truncation or resampling.

## Hypothesis
At F = 12, every one of the 10 committed integer operators stays inside the BF16 reference's own error envelope: on each of the 5 held-out runs, R_max = max|int - bf16| / max|bf16 - fp64| <= 2.

## Metric
Per (op, arm, F, run), over the run's output elements (excluding norm out-of-domain vectors):
- max abs error and RMS error of the integer pipeline vs the arm's reference (`int-ref`), of the reference vs FP64 (`ref-fp64`) and of the integer pipeline vs FP64 (`int-fp64`, context);
- envelope ratios R_max = max|int - ref| / max|ref - fp64| and R_rms = rms(int - ref) / rms(ref - fp64) (if a denominator is 0 and its numerator is not, the ratio is +inf);
- integer clamps, integer out-of-domain vectors, FP8 saturations and FP8 underflows to zero (input elements), BF16 overflows;
- sign flips: output elements with int * ref < 0;
- argmax flips, for the vector ops only (conv per 4-output chunk, l2, rms, rotary per vector): argmax of int differs from argmax of ref (ties broken to the lowest index).
Across the 5 runs: median, sample SD, min, max of each.

## Acceptance threshold
Decision cell = (arm, F), 6 cells. A cell PASSES iff R_max <= 2 for all 10 ops on all 5 held-out runs (50 checks, no median, no exclusions besides the norm out-of-domain rule above). The hypothesis is the cell (BF16, F = 12). The other five cells are registered secondary cells under the same rule. Sign and argmax flips, R_rms, clamps and saturations are reported, not part of the rule. Calibration and stress numbers are never used for the verdict.

## Prior art
- Upstream FlashProve reports 6.81% top-token disagreement and 0/96 whole-reply exact matches per stock precision, Python-scored on other programs and not reproduced here (#8 body).
- In this repo: `qwen-real-weights-layer0` (PR #68), `qwen-norm-scaling-layer0` (PR #74) and `qwen-q1-deep-fidelity` (PR #88) compare integer DeltaNet head lowerings with a float64 reference on real weights; PR #67 measured the qwen_ops tables against float64 on dequantized integer inputs. None of them defines a BF16 or an FP8 reference; #74 has one "BF16 emulation" descriptive number with no format specification. What is new here: written, separate BF16 and FP8 reference definitions (format, rounding, saturation, accumulation, scale granularity and calibration), real-valued inputs (input conversion error included), frozen calibration/held-out splits, and envelope ratios against each reference. Nothing here is about real weights or whole models.
- zkML: EZKL reports quantization error of its fixed-point circuit against the float ONNX output (per output, with a tolerance setting); zkLLM (Sun et al., 2024) reports perplexity of its quantized proved model against the float model. Neither separates BF16 from FP8 references.
- Formats: OCP 8-bit Floating Point Specification (OFP8) rev 1.0 (2023), E4M3 and E5M2, saturation behaviour; Micikevicius et al., "FP8 Formats for Deep Learning" (2022), per-tensor delayed scaling; NVIDIA Transformer Engine recipes (delayed / current scaling).
- Per-layer error studies: LLM.int8() (Dettmers et al., 2022) and SmoothQuant (Xiao et al., 2022) measure per-layer activation/weight quantization error and outliers; this lane borrows the per-operator error and saturation accounting, at operator level only.
