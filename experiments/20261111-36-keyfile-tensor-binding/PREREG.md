# PREREG: 20261111-36-keyfile-tensor-binding
Issue: #36. Lane: keybind36. Date (UTC): 2026-11-11. Base commit: cf4b213 (origin/main at clone).

## Hypothesis
A versioned research key-file extension on the existing CPU small-key proof fixture can bind every tensor block of its committed matrix to verifier-held checkpoint and conversion manifests through per-block multilinear evaluation claims inside the key's LIN proof, accepting honest controls and refusing each named substitution below.

## Metric
Measure complete serialized key bytes and verifier wall time in milliseconds with steady_clock. Record each verdict, rejection stage, key-byte count, seed, and timing in raw JSON. Compare legacy key files and bound key files on the same fixture. Count manifest bytes, block dimensions, linear-claim counts, and extrapolated payload counts separately. No timing speedup claim. Scope is the existing `blocks/frame/tests/small_key_test.cpp` CPU proof machinery and its 4 by 4 weight matrix, partitioned into four named row tensors. This is a research profile, not a production cp_verify model or a Qwen proof.

## Acceptance threshold
All 10 honest legacy and 10 honest bound controls accept. Each of five negative arms refuses in 10/10 trials: one tensor swapped, two tensors swapped, tensor order permuted, manifest root of another checkpoint, conversion-id mismatch. Swapped tensors use a different in-range witness, not malformed bytes. Their proofs must fail in the proof checks when the prover attempts the verifier's held statement, rather than merely fail an outside file hash. Include self-consistent alternate-checkpoint and alternate-conversion controls that accept. A wrong-manifest replay may additionally fail in transcript checking; distinguish this from the attempted false evaluation claim. All tensor blocks must be tied to fixed matrix addresses. Root/identity checks alone do not meet the substitution threshold. Any failure is reported FAIL, not hidden by changing the threshold.

## Prior art
- zkLLM (https://arxiv.org/abs/2404.16109) uses committed tensors with proof relations for LLM operations; it is not checkpoint provenance by itself.
- EZKL model commitments (https://docs.ezkl.xyz/) and Modulus/zkML weight commitments (https://github.com/modulus-labs) bind a model/weight representation to a statement. This lane is not a new general commitment scheme.
- Safetensors (https://github.com/huggingface/safetensors) separates tensor names, shapes, dtype, and byte ranges. Per-tensor hashing avoids conflating container header changes with tensor changes.
- OpenSSF model signing / Sigstore model transparency (https://github.com/sigstore/model-transparency) authenticates artifact provenance, not execution under the named weights.
- Main PR #87 implements checkpoint manifests and designs DESIGN 2.2; PR #100 binds conversion/configuration identities at hash level. Neither adds per-tensor evaluation claims to a key proof. The bounded new work is a CPU research key-file/verifier path using the existing WF/BATT/LIN machinery, with the expected evaluations derived after the committed table's ID, and adversarial swapped-witness tests. No new soundness level, Fiat-Shamir security bound, full-model support, or proof of abliteration detection is claimed.
